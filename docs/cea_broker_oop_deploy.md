# CEA broker decision deployment (#427, alfred#51)

This change is **off by default**. `AGENT_CREW_CEA_BROKER_SOCKET` selects the broker decision client. The broker speaks the existing authenticated engine service intent format through a new `authorize` operation. A missing or unreachable socket falls back to the embedded engine and stamps `downgrade_reason: broker_unreachable` on its receipt. Embedded `enforce` still refuses authorization, so a failed broker cannot grant work.

## Phase 1: integrity by convention

The live sudoers rule currently points to `/home/truhojun/alfred/tools/cea/broker-launch.sh`. Its path and the broker source tree have user-writable ancestors. This phase is a policy gate for honest mistakes, **not** an adversarial isolation boundary. The launcher `--check` and broker inspect file and ancestor ownership/modes. A writable or non-root-owned component forces `BROKER_TREE_USER_WRITABLE` on all decision receipts and prevents any `VERIFIED` executor attestation. `BLOCKED` peer/registration evidence still takes precedence.

1. Build and stage `/opt/agent_crew-authz/src` from the reviewed commit; keep `src.old`, write `/opt/agent_crew-authz/SRC_COMMIT`, and verify both source and launcher SHA-256. Do this as a separate, manual T0 action. `scripts/cea/install_broker.sh` stages the tracked launcher byte-identically at the existing pinned path with mode 0755 and verifies SHA-256; it does not edit sudoers or start the broker.
2. Write `/opt/agent_crew-authz/broker.env` with `AGENT_CREW_CEA_BROKER_DB` pointing to the alfred queue DB, `AGENT_CREW_CEA_CALLER_TOKENS` to the private adapter token table, `AGENT_CREW_CEA_MODE=enforce`, and `AGENT_CREW_CEA_ENFORCE_CODES=RUNTIME_STATE_FORBIDS`. Configure the broker's input paths as documented in `cea/wiring.py` and set `AGENT_CREW_CEA_SNAPSHOT_PUBKEY_FILE` to the snapshot producer's Ed25519 public key (PEM or raw 32 bytes). Give the broker only this public key; do not copy the producer's HMAC signing key into the broker or set `AGENT_CREW_CEA_SNAPSHOT_KEY_FILE` there. Its token file must be readable by `crew-authz` and mode 0600 or 0400. The launcher sources this fixed config path after sudo clears the caller environment.

`broker.env` is sourced by Bash, so every non-comment line must be a single `KEY=VALUE` assignment. Quote values containing spaces or shell punctuation with `shlex.quote` style single quotes; for example, `AGENT_CREW_CEA_CREDIT_CLASS='{"gemini":"plan"}'`. The owner setup script checks existing lines and the final file with `bash -n` and an empty-environment source round-trip before either dry-run or apply proceeds. It refuses malformed lines and all `*_CMD` keys, including `AGENT_CREW_CEA_MEMORY_CMD`; do not put executable commands in broker config.
3. Run `AGENT_CREW_CEA_BROKER_LAUNCHER=/home/truhojun/alfred/tools/cea/broker-launch.sh scripts/cea/start_broker.sh --check`. Inspect the reported downgrade. Start the broker through the same configurable launcher path. Check the socket and test a credentialed decision before changing the crew server.
4. In a sandbox, run `python3 scripts/cea/broker_sandbox.py` and `RUN_CEA_BROKER_SANDBOX=1 pytest -q tests/unit/test_cea_broker_sandbox_wrapper.py`. Evidence is written to `evidence/cea_broker_sandbox_<sha7>.json`. The decision assertions use a separate isolated broker with injected providers; the launched degraded broker and free-port server are smoke checks. This does **not** constitute a live deploy test.
5. Prepare the T0 swap with `scripts/runtime_swap.sh`: target project `alfred`, exact build SHA and artifact SHA-256, launch command, before/after process PID and port, broker socket path and owner/mode, token-table path and mode, source commit, `--check` output, allowed reason-code set, receipt IDs for blocked/allowed/advisory probes, and rollback owner. Set `AGENT_CREW_CEA_BROKER_SOCKET` on the crew server only during the approved swap. The socket path alone does not make a receipt `VERIFIED`.

The broker launcher path is configurable with `AGENT_CREW_CEA_BROKER_LAUNCHER`; the default in `scripts/cea/start_broker.sh` is the phase-2 root-owned path. The old path must be specified explicitly and is phase 1 only.

## Phase 2: owner root step

`scripts/cea/install_broker_root.sh <full-build-sha>` prints the owner entrypoint. The owner reviews `scripts/cea/owner_root_enforce_setup.sh --dry-run` and its SHA-256, then runs `sudo scripts/cea/owner_root_enforce_setup.sh --apply --caller-tokens /path/to/private/adapter-tokens.json` during the approved T0. The token source must be supplied explicitly if no existing `broker.env` names it. The script copies the table to `/opt/agent_crew-authz/caller-tokens.json` as `crew-authz:crew-authz` mode 0400; it never grants broker access to `~/.verify-private`. It copies only the Ed25519 public key from `/home/truhojun/alfred/governance/ssot-producer-ed25519.pub` by default; pass `--snapshot-pubkey /path/to/public-key.pem` to select another PEM source. The installed `/opt/agent_crew-authz/snapshot.pub` is `root:crew-authz` mode 0644, and `broker.env` points to it with `AGENT_CREW_CEA_SNAPSHOT_PUBKEY_FILE`. The broker build must include the verifier from #443 before apply.

The script creates a dedicated `crew-authz-clients` group for `truhojun` and `crew-authz`. It installs `acl` if needed and grants only traverse on `~/.agent_crew`, `rwx` on the alfred queue directory, and `rw` on `tasks.db` to `crew-authz`. The queue database is the broker's independent runtime state and executor binding evidence; trusting fields supplied over the socket would weaken authorization. SQLite uses `journal_mode=delete` here, so the broker needs directory write for a hot journal or SQLite journal creation as well as database read/write. The launcher moves to `/usr/local/libexec/crew-authz/broker-launch.sh`; the tree becomes root-owned without group/other write, and sudoers is validated with `visudo -cf` on a temporary file before replacement. Apply runs an installed-path authenticated receipt proof, then the launcher `--check` as `crew-authz` and requires `downgrade_reason=none`. The root-owned `/opt/agent_crew-authz/venv` is built from `scripts/cea/broker-requirements.txt`; the launcher uses this interpreter and `--check` prints dependency versions. The frozen receipt schema is installed under `/opt/agent_crew-authz/tests/cea_contract/` and a missing schema fails broker startup and `--check`.

`sudo scripts/cea/owner_root_enforce_setup.sh --undo` restores the pre-apply broker tree, launcher directory, sudoers, ACLs, group memberships, and any package/group created by apply from `/var/lib/crew-authz/owner-root-enforce/manifest.json` and its backups. Run undo before another apply; keep this manifest until the phase is accepted. Every later broker code update requires another reviewed root installation into `/opt/agent_crew-authz`.

For a reviewed broker code update, run `scripts/cea/owner_root_enforce_setup.sh --update-src` to inspect the plan, then `sudo scripts/cea/owner_root_enforce_setup.sh --apply --update-src` from a clean checkout of that commit. This single apply stages the source, frozen schema, pinned venv, caller tokens, and launcher; normalizes root-owned directories to 0755 and source files to 0644; and keeps the caller token table `crew-authz:crew-authz` 0400. It tests the installed paths as `crew-authz` in a clean environment with no user site, checks an authenticated schema-valid receipt with no downgrade, and restarts through the sudoers-pinned launcher. A failure restores the previous paths. Temporary backups are removed after success so the next update needs no owner cleanup. Stale `src.old` or `src-update.json` blocks dry-run with a recovery command. The launcher supports `--start`, `--stop`, `--restart`, and `--health` with a pidfile verified against `/proc` before signaling.

Both non-root previews print the full plan if the existing root-owned `broker.env` cannot be read; they say `existing broker.env unreadable as non-root; validated at apply`. Root apply validates that file and runs a disposable pre-install broker proof before changing installed files. The proof stages the candidate source and receipt schema, starts a broker as `crew-authz` in a temporary `0710` socket directory owned by `crew-authz:crew-authz-clients`, then connects as uid 1000 with the client group and presents a token from `--caller-tokens`. It checks authenticated authorize, peer uid, and socket `crew-authz:crew-authz-clients 0660`, printing JSON evidence. A failed proof aborts before the installation manifest or tree changes. `python3 scripts/cea/broker_group_sandbox.py --caller-tokens /path/to/private/adapter-tokens.json` exercises the group and socket path without root in a disposable directory.

The broker socket has group `crew-authz-clients` and mode 0660. A crew server started before group enrollment cannot use new membership inherited from its old process. The swap launcher uses `sg crew-authz-clients` for the new server when `AGENT_CREW_CEA_BROKER_SOCKET` is set; preflight and `go` test a socket connection through that same launcher before stopping the old server. A manual server launch must likewise use a fresh login with the group or `sg crew-authz-clients -c '<server command>'`.

## Rollback

Unset `AGENT_CREW_CEA_BROKER_SOCKET`, swap the crew server back to the recorded pre-change build with `scripts/runtime_swap.sh`, and verify `/health`, process PID/port, and a fresh receipt. Stop the broker after the server no longer points at its socket. Do not alter the live sudoers rule outside the phase-2 owner step. Preserve the evidence and failed receipts for review.
