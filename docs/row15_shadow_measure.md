# ADR-001 row 1.5 shadow measurement (#431, #398)

Run `PYTHONPATH=src:. python3 scripts/measure_row15_shadow.py --output evidence/row15_shadow_measure_<sha7>.json` from this checkout. The script opens each live task DB and the live memory DB through SQLite `mode=ro`. It copies the memory DB with SQLite backup into a temporary DB before calling `RuntimeMemoryProvider`, whose storage adapter opens a normal connection. The rollback probe creates its task and memory DBs under a temporary HOME and uses a free port only as app configuration; HTTP requests go through FastAPI `TestClient`, with no live listener.

The committed evidence artifact records the exact sample and timing. The sample is selected by `claim_build_commit` beginning with `a138976` and terminal status; fixture IDs are excluded. This criterion found 8 agent_crew tasks, 2 quota-ops tasks, and no alfred tasks. It cannot establish alfred behavior on that build. All 10 selected tasks have the expected episodic and decision rows (and failure pattern for non-completed outcomes). The artifact lists missing IDs if a later run finds any and reports each scope field's fill count. Snapshot and task DB reads are sequential, so a concurrent terminal result can alter a repeat run's sample.

The retrieval comparison uses the existing runtime shadow provider and K4 lexical candidate provider, both wrapped by `shadow_retrieve`. K4 lexical is a corpus baseline over the same snapshot; its top ten are selected before the wrapper removes cross-project candidates, so fewer than ten retained hits can reflect that order. Runtime retrieval restricts candidates to the project in SQL. The run is retrospective: outcomes already captured for sampled tasks can appear at rank one. Same-task and same-issue ranks therefore describe observed scope behavior after completion, not recall available before those tasks ran. No ranking success rate should be inferred for prospective dispatch from this sample.

The rollback probe starts a fresh app lifespan for each stage. It flips both shadow retrieval and capture flags on/off/on and submits one sandbox task per stage. The artifact includes elapsed time from app creation through result and capture count. HTTP and task statuses establish that the off stage accepted the result while writing zero capture rows; the final on stage restored two rows. The probe uses direct queue enqueue without an execution claim, which can produce a CEA shadow lifecycle warning unrelated to memory capture; all three task results remain HTTP 200.
