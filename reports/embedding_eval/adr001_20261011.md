**BAAI/bge-m3 was not re-run on this snapshot.** Its October 9 warm-index
measurement on 4,271 rows was 9/17 owner recall, 0/24 task recall, 590.6 ms
p95 embed, 685.6 ms p95 retrieve, and 2,284.6 MB model size
([historical report](adr001_20261009.md)). The prior retrieval p95 exceeded
the 300 ms gate by more than 2×, and warming this 2.3 GB model on the expanded
10,245-row corpus was outside this re-run. Those older figures are not
current-corpus results and cannot establish BGE's October 11 recall or latency.

**Chosen model_id under the October 11 re-run criterion: none.** The re-run
instruction required improving both owner (M3a) and task (M3b) recall over
`lexical_only`, as well as retrieval p95 at or below 300 ms. No vector model
improved task recall (all measured models returned 4/24). E5 also exceeded
the latency limit. M3a/M3b are labels from the re-run instruction; this repo
does not define them as a model-selection rule.

**Issue #676's literal selection rule would choose
`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` among the
measured multilingual candidates.** It asks for the best model meeting
retrieval p95 <=300 ms, without requiring an improvement on both recall sets.
Paraphrase scored 11/17 owner versus the lexical baseline's 10/17 at 214.4 ms
p95; task recall tied at 4/24. E5 was above the latency limit. The 12/17
`all-MiniLM-L6-v2` result is an English-only control, excluded from the
multilingual choice by #676. BGE's missing October 11 measurement limits this
comparison to the multilingual models actually re-run.

The copied corpus contains at least one expected source for 17/17 owner cases
and 12/24 task cases, as confirmed independently by
`scripts/backfill_task_outcomes.py`'s audit. The task references name issues,
PRs, and review IDs, while the stored rows use `task_outcome:` keys; the eval
resolves those references to stored keys with the audit's rules before scoring.
The remaining 12 task cases are outside this snapshot's source coverage.

Method: each model used a separate copy of the same snapshot. All rows were
embedded offline before scoring, with no retrieval deadline during warmup;
the lexical baseline created no vectors. Retrieval called A2
`HybridMemoryStorage.retrieve_ranked` with project scope, `k=10`, a 65,536-byte
middle budget, and its normal 300 ms deadline. A case is a hit when any expected
stored key appears in the head or middle. P95 is nearest-rank over 41 queries;
embedding p95 covers query tokenization and ONNX inference, excluding offline
warmup. E5 uses `passage:` for stored text and `query:` for queries.

The table uses the second sequential scoring pass, taken after all warmups
finished and with no competing eval workers. It had 41 lexical-only responses;
the vector modes were MiniLM 39 hybrid/1 lexical-only/1 fallback,
paraphrase 40 hybrid/1 lexical-only, and E5 36 hybrid/1 lexical-only/4
fallback. On the immediately preceding pass, retrieval p95 ranged from
132.1 ms (MiniLM) to 432.4 ms (lexical), with three lexical deadline fallbacks.
Host load therefore affects latency and even deadline-limited recall; these
figures are measurements from this host, not a guarantee for another load.

Reproduce after making a SQLite online backup of the live DB to a temporary
`source-snapshot.db`:

```bash
PYTHONPATH=src python3 scripts/eval_embedding_models.py \
  --db /tmp/adr001-r5-20261011/source-snapshot.db \
  --resume-dir /tmp/adr001-r5-20261011 \
  --models lexical_only all-MiniLM-L6-v2 \
    sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 \
    intfloat/multilingual-e5-small \
  --output /tmp/adr001-r5-results.json
PYTHONPATH=src python3 -m pytest -q tests/unit/test_eval_embedding_models.py
```

The model cache and database copies were outside the repository.
