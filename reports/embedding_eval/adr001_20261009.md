**Chosen multilingual model_id:** `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`.
The English-only control and lexical baseline are excluded from model selection.
It ties E5 at 6/17 owner hits and has the lower eligible p95 retrieval time.
Neither eligible multilingual model improves on the lexical baseline's 8/17;
BGE-M3 reaches 9/17 but exceeds the 300 ms retrieval limit.

**Vector coverage before scoring:**

- `intfloat/multilingual-e5-small`: 4,271/4,271 rows; modes {'hybrid': 36, 'lexical_only': 5}; fallbacks 0.
- `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`: 4,271/4,271 rows; modes {'hybrid': 36, 'lexical_only': 5}; fallbacks 0.
- `BAAI/bge-m3`: 4,271/4,271 rows; modes {'fallback': 21, 'hybrid': 15, 'lexical_only': 5}; fallbacks 21.
- `all-MiniLM-L6-v2`: 4,271/4,271 rows; modes {'hybrid': 36, 'lexical_only': 5}; fallbacks 0.
- `lexical_only`: 0/4,271 rows; modes {'lexical_only': 41}; fallbacks 0.

**Corpus coverage limit:** all 17 owner cases have at least one exact expected
memory key in the copied DB; none of the 24 task cases has an exact expected
reference as a memory key. Thus task recall is constrained by missing corpus
records, not just ranking quality.

Method: Each model copied the same frozen source snapshot and pre-embedded all
4,271 rows into the copy with no retrieval deadline. Embeddings used batched CPU
ONNX inference; E5 corpus text received `passage:` and queries received `query:`.
The earlier cold run started with no vectors. A2's lazy path can embed at most
two candidate rows per query, or at most 82 over these 41 cases, so its recall
and model choice were not a warm-index comparison. This report supersedes it.
Only after full vector coverage did the script run A2
`HybridMemoryStorage.retrieve_ranked` with `MemoryScope(project=...)`, `k=10`,
a 65,536-byte middle budget, and the normal 300 ms retrieval deadline.
A case counts as a hit when any expected key appears exactly in the returned
head or middle. P95 uses the nearest-rank 41-query sample. Embed timing includes
query tokenization and ONNX inference but excludes the offline corpus warmup.
The lexical baseline created no vectors. The ONNX weights and tokenizers live
in caches outside the repo.
